## 1. 总体架构

B/S 前后端分离，企业内部单实例部署。

```
浏览器 ──HTTP/JSON──► 后端 ──JDBC──► MySQL 8.0
                        └──Redis──► 会话缓存
```

后端 `Controller → Service → Mapper` 三层。判定逻辑集中在单一服务类，新增判定方式只改一处。

## 6. 认证与权限

- Spring Security 7 + JWT 无状态认证，令牌同步写入 Redis，登出即失效；
- 角色三种：`ENGINEER` / `INSPECTOR` / `ADMIN`，存于用户表单列，不建角色表；
- 权限在**接口层**用方法级注解校验，不依赖前端隐藏菜单；
- 密码 BCrypt 存储。

---

## 7. 关键约束

| 约束 | 说明 |
|---|---|
| 业务表 ≤ 6 张 | 不引入通用权限框架，不建部门、岗位、字典、菜单表 |
| 判定只在服务端 | 前端结果仅展示，提交后服务端重算 |
| 记录保存标准快照 | 改标准不回溯历史记录 |
| 只作废不删除 | 统计排除作废记录 |
| 三场景共用一套模型 | IQC / PQC / OQC 为 `scene` 字段，不做三套页面 |
| 缺陷状态顺序流转 | OPEN → PROCESSING → VERIFIED → CLOSED，禁止跳级 |
| 判定规则集中一处 | 新增判定方式只改一个服务类 |
| 图表实时查询 | 不做预聚合表，数据量小 |
